# Armory Ledger

Armory Ledger is a self-hosted firearm, ammunition, and related inventory management application.

The project is designed primarily for private, self-hosted use, with an emphasis on inventory history, ownership isolation, provenance, maintenance, ammunition tracking, and long-term record keeping.

Armory Ledger is currently under active development.

## Features

Current foundation:

- Multi-user ownership-aware data model
- Firearm inventory schema
- Ammunition products, lots, and inventory transaction ledger
- Manufacturer and organization relationship tracking
- Caliber aliases and normalized caliber records
- Authentik OIDC authentication
- Group-based user and administrator authorization
- Persistent internal user identities
- PostgreSQL database
- Alembic database migrations
- Docker Compose deployment
- Cloudflare Tunnel support
- Health monitoring endpoint

Planned functionality includes:

- Firearm inventory management
- Ammunition inventory and lot tracking
- Purchases and receipts
- Accessories and magazines
- Range session logging
- Maintenance history
- Safety notice and recall tracking
- Document and photograph storage
- Inventory exports
- User notification preferences

## Architecture

Armory Ledger currently uses:

- FastAPI
- PostgreSQL 17
- SQLAlchemy
- Alembic
- Authlib
- Authentik OIDC
- Docker Compose
- Cloudflare Tunnel

The intended deployment path is:

    Internet
       |
       v
    Cloudflare
       |
       v
    Cloudflare Access
       |
       v
    cloudflared
       |
       v
    Armory Ledger
       |
       v
    PostgreSQL

The application and Cloudflare Tunnel share a frontend Docker network.

Armory Ledger and PostgreSQL share a separate internal backend network. PostgreSQL is not exposed directly to the frontend network or host.

## Authentication

Armory Ledger does not maintain local passwords.

Authentication is handled through Authentik using OpenID Connect (OIDC). Armory Ledger maintains its own internal user UUID and associates it with the immutable OIDC subject (`sub`) supplied by Authentik.

Email addresses and display names are synchronized from the identity provider during login without changing the internal Armory Ledger user ID.

The current Authentik groups are:

- `Armory User` — permits access to Armory Ledger
- `Armory Admin` — grants application administration privileges

Administrator privileges do not inherently grant access to another user's private inventory.

## Configuration

Copy the example environment file:

    cp .env.example .env

Then configure the required values in `.env`.

The configuration includes:

- PostgreSQL credentials
- Cloudflare Tunnel token
- Authentik OIDC client ID and secret
- Authentik OIDC issuer
- OIDC callback URL
- Application session signing secret

A session secret can be generated with:

    python3 -c 'import secrets; print(secrets.token_urlsafe(64))'

Never commit `.env` to source control.

## Cloudflare Tunnel

The included Docker Compose configuration supports running `cloudflared` alongside Armory Ledger.

Configure the Cloudflare Tunnel service URL as:

    http://armory-ledger:8000

The Armory Ledger application does not require its port to be published directly to the Docker host when accessed through the tunnel.

## Running Armory Ledger

Build and start the application:

    docker compose up -d --build

Check container status:

    docker compose ps

The health endpoint is available at:

    /health

A healthy installation returns information similar to:

    {
      "status": "healthy",
      "application": "Armory Ledger",
      "database": "connected",
      "version": "0.1.0"
    }

## Database Migrations

Apply all available migrations:

    docker compose exec armory-ledger alembic upgrade head

Check the current migration:

    docker compose exec armory-ledger alembic current

When developing through Docker, a new migration can be generated directly into the host source tree with:

    docker compose run --rm -T \
      --user "$(id -u):$(id -g)" \
      -v "$PWD:/app" \
      armory-ledger \
      alembic revision --autogenerate -m "migration description"

Always review autogenerated migrations before applying them.

## Data and Security

Armory Ledger is intended to contain sensitive personal inventory information.

The repository deliberately excludes:

- `.env`
- Authentication secrets
- Cloudflare Tunnel credentials
- OIDC client secrets
- Session signing secrets
- User-uploaded documents

Uploaded documents are stored under `storage/documents/` and are excluded from Git except for the directory placeholder.

Private inventory records are associated with an internal Armory Ledger user ID. Application authorization must enforce ownership server-side rather than relying on frontend visibility controls.

## Development Status

Armory Ledger is currently in early development.

Version `0.1.0` establishes the initial database schema, containerized deployment, Cloudflare Tunnel ingress, Authentik OIDC authentication, group authorization, and persistent internal user identity.

The database and architecture are expected to evolve as inventory functionality is implemented.
